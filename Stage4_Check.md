## 0. Подготовка

**Только копия БД и копия хранилища.** До миграции у всех файлов нет маркера, и при сохранении сборки каждый неотмеченный компонент получит новую версию. В рабочей БД это засорит историю.

1. Копия БД:
   ```bash
   pg_dump -h <host> -U <user> -Fc -f agrovent.dump <рабочая_БД>
   createdb -h <host> -U <user> agrovent_test
   pg_restore -h <host> -U <user> -d agrovent_test agrovent.dump
   ```
2. Тестовая папка хранилища, например `D:\AgroventTest\Storage`. Скопировать в неё папки `<hash>` только тех компонентов, которые будут в тестах (или пустую — тогда тестовые изделия создаются с нуля).
3. `Agrovent/Resources/appsettings.json`: `ConnectionStrings:DefaultConnection` → `agrovent_test`, `Storage:StorageRootFolderPath` → тестовая папка, `Storage:LocalWorkFolder` → например `D:\AgroventTest\Work`. **После проверки вернуть.**
4. Снять замки в тестовой БД: `DELETE FROM public."ComponentEditLocks";`
5. Тестовое изделие (собрать из новых файлов, чтобы ничего не зависело от старых данных):
   - сборка `T-A` → подсборка `T-B` (→ детали `T-P1`, `T-P2`) + деталь `T-P3` (листовая) + покупной компонент;
   - чертёж (.slddrw с тем же именем) у `T-P1` и у `T-A`.
6. Логи: окно Output в VS (логгер Debug). Полезно фильтровать по словам «Маркер», «План», «Отпечаток», «Хранилище».
7. В CommandManager появились две временные кнопки: **«Маркер и отпечаток»** (при открытой детали/сборке) и **«Миграция: отчёт»** (только когда нет открытых документов). Если кнопок не видно, сбросить вкладку CommandManager (ПКМ → «Сбросить»/перезапуск SolidWorks: группа команд изменилась).

«Маркер и отпечаток» показывает маркер, отпечаток из маркера, текущий отпечаток, «Обозначение» файла и каждой конфигурации и пишет каноническую строку в `Документы\Agrovent\Fingerprint\<имя>_<время>.txt`. Два таких файла сравниваются любым diff (WinMerge, VS: `devenv /diff a.txt b.txt`).

### SQL для проверки (тестовая БД)

```sql
-- Версии компонента (подставить обозначение)
SELECT c."PartNumber", v."Id", v."Version", v."BasedOnVersion", v."HashSum", v."SavedByUserId", v."CreatedAt"
FROM public."ComponentVersions" v JOIN public."Components" c ON c."Id" = v."ComponentId"
WHERE c."PartNumber" = '<PN>' ORDER BY v."Version";

-- Файлы версии
SELECT f."FileType", f."FilePath" FROM public."ComponentFiles" f WHERE f."ComponentVersionId" = <VersionId>;

-- Состав версии сборки
SELECT c."PartNumber", ch."Version", s."Quantity", s."Order"
FROM public."AssemblyStructures" s
JOIN public."ComponentVersions" ch ON ch."Id" = s."ChildComponentVersionId"
JOIN public."Components" c ON c."Id" = ch."ComponentId"
WHERE s."ParentComponentVersionId" = <VersionId> ORDER BY s."Order";

-- Замки
SELECT c."PartNumber", l."UserId", l."BaseVersion", l."MachineName", l."CreatedAt"
FROM public."ComponentEditLocks" l JOIN public."Components" c ON c."Id" = l."ComponentId";

-- Свойства версии
SELECT p."Name", p."Value", p."UpdatedAt" FROM public."ComponentProperties" p WHERE p."ComponentVersionId" = <VersionId> ORDER BY p."Name";
```

## 9. Чужой замок

Второй пользователь не обязателен, можно вставить замок SQL-запросом:
```sql
INSERT INTO public."ComponentEditLocks" ("ComponentId","UserId","BaseVersion","MachineName","CreatedAt")
SELECT c."Id", <Id другого пользователя из "Users">, 1, 'TEST', now() FROM public."Components" c WHERE c."PartNumber" = '<PN T-P2>';
```
1. Открыть `T-A` → «Взять на редактирование»: `T-P2` недоступен, показан владелец.
2. Взять `T-A` и `T-P1` (`T-B` отметится сам), сохранить → сохранение остановлено: «`T-P2` на редактировании у <фамилия имя>». Так задумано в плане сохранения: чужой замок на любом компоненте сборки = стоп, даже если компонент не менялся. Если это неудобно в работе — скажи, обсудим.
3. Удалить тестовый замок: `DELETE FROM public."ComponentEditLocks" WHERE "MachineName" = 'TEST';`
